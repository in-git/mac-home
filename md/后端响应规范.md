# Skill：后端响应规范
## 适用场景
开发人员询问项目统一返回格式、状态码含义、分页出入参结构、前端异常处理逻辑时启用，严格依照文档内容回复，禁止自定义新增状态码与字段。

## 一、响应结构
统一JSON格式，共4个字段：

| 字段    | 类型   | 说明                     |
| ------- | ------ | ------------------------ |
| code    | Number | 状态码                   |
| msg     | String | 提示语                   |
| data    | Object | 返回数据（仅成功时返回） |
| traceId | String | 跟踪ID（排障用）         |

## 二、状态码
| code             | 说明                           |
| ---------------- | ------------------------------ |
| 200              | 成功                           |
| 401              | 未登录，token缺失或无效        |
| 403              | 无权限/无角色/账号被封禁       |
| 405              | 请求方法错误（GET/POST不匹配） |
| 415              | 参数校验或格式错误             |
| 500              | 服务器异常/数据操作异常        |
| 1011007、1011008 | token失效，需重新登录          |

## 三、前端处理规则
- code=200：正常处理data
- code!=200：提示msg内容
- code为401、1011007、1011008：跳转登录页

## 四、分页规范
### 请求参数
| 参数      | 类型   | 默认 | 说明                |
| --------- | ------ | ---- | ------------------- |
| current   | Number | 1    | 页码                |
| size      | Number | 20   | 每页条数（最大100） |
| sortField | String | 无   | 排序字段（驼峰命名）|
| sortOrder | String | 无   | 排序方向            |

### 公共排序字段
排序字段 `sortField` 与排序方向 `sortOrder` 为框架通用约定（对应 `CommonSortOrderEnum`），所有分页接口均可选传：

| 字段      | 说明                                                         |
| --------- | ------------------------------------------------------------ |
| sortField | 排序字段，传实体属性驼峰名，后端自动转为数据库下划线字段名   |
| sortOrder | 排序方向：升序传 **ASCEND**，降序传 **DESCEND**              |

- `sortField` 与 `sortOrder` 需同时非空才生效，缺一则忽略排序；
- `sortOrder` 仅支持 `ASCEND` / `DESCEND`，传入其他值将抛出 `不支持该排序方式` 异常。

### 返回结构（data内部）
| 字段    | 类型   | 说明     |
| ------- | ------ | -------- |
| records | Array  | 数据列表 |
| total   | Number | 总条数   |
| current | Number | 当前页   |
| size    | Number | 每页条数 |
| pages   | Number | 总页数   |

## 应答约束
1. 输出结构、字段名称、状态码数值严格与文档保持一致，不得随意修改；
2. 不允许新增文档不存在的自定义状态码；
3. 分页size上限固定为100，不能放宽；
4. 当用户需要示例JSON时，可以基于规范组装标准样例。

## 兜底规则
超出本文档范围的返回格式问题，请确认后端Controller统一响应处理器配置。
