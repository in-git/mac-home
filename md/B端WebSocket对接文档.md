# B端 WebSocket 对接文档

## 1. 业务场景

站内信实时通知。用户登录后,前端与后端建立 WebSocket 长连接,用于接收未读消息数的实时推送,无需轮询。

## 2. 连接端点

后端暴露端点:`/dev/message/ws`(原生 WebSocket,非 STOMP)。

## 3. 鉴权逻辑

- 连接时通过 query 参数 `token` 携带登录凭证。
- 后端用 Sa-Token 校验 token:无效或未传则立即关闭连接,合法则建立连接并绑定 `userId ↔ session`。

## 4. 推送逻辑

- **连接建立时**:服务端主动查询该用户的未读消息数并立即推送一次。
- **产生新消息时**:业务侧(发消息接口)调用 `DevMessageWebSocket.sendMessage(userId)`,向该用户的所有连接推送最新未读数。
- **推送粒度**:按 `userId` 维度,仅推送给目标用户,不影响其他用户。

## 5. 消息格式

服务端推送文本(JSON 字符串):

```json
{ "code": 200, "data": 0 }
```

- `code`:200 表示正常推送
- `data`:业务数据,当前为未读消息数(Long)

## 6. 连接生命周期

- 多标签页会建立多个连接,均按 `userId` 绑定,互不影响。
- 应用关闭时服务端优雅关闭所有连接。

## 7. 注意事项

- 前端无需自动重连(当前服务端不推送心跳,业务为连接即下发一次未读数)。
- 浏览器不支持 WebSocket 时,前端给出功能不支持提示。
