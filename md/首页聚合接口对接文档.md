# 首页聚合接口对接文档

> 用途：一次请求返回首页除分类外的全部区块数据，替代前端目前「常规列表 + 推荐 + 最新 + 最热」的多次串行请求。
> 本文只声明**前端需要后端提供哪些数据**，不定义后端字段名、不写响应示例。字段命名与返回结构请遵循《后端响应规范》，站点字段以《站点公开接口对接文档》的 `BizSitePublicVo` 为准。

## 一、接口划分

首页数据分两路，**互不合并**：

| 数据 | 是否需要独立接口 | 原因 |
| --- | --- | --- |
| 分类树 | **需要，且单独查询** | 分类树的入参只有 `module`，不随分类 / 搜索变化，且首屏要在列表请求之前先拿到（用于确定默认分类）。与列表数据没有共同入参，合并会多带一份无意义的筛选条件。 |
| 其余全部区块 | 合并为一个聚合接口 | 都由同一批入参驱动，合并可省掉首屏的多次串行请求。 |

分类树沿用已有的 `/public/site/categoryTree`，**不在本次聚合范围内**，下文不再讨论。

## 二、聚合接口需要哪些数据

### 1. 头条区超大卡（1 条）

- **使用推荐数据**：取推荐站点中的 1 条作为超大卡展示，与下方「推荐站点」同源。
- 因此该数据不占用常规列表，**不需要从常规列表结果中剔除**。
- 推荐数据为空时该卡为空，前端降级为占位、不渲染头条区。

### 2. 头条区排行榜（两个榜，各 5 条）

宫格左侧是「最新 / 最热」可切换的排行榜，两个榜需要**同时**返回，前端切 tab 时不再发请求。

- **最新榜**：按创建时间由新到旧，第 1 条即最新发布，前端按返回顺序渲染名次 1..5。
- **最热榜**：按点击量由多到少，前端按返回顺序渲染名次 1..5。
- 两个榜都需要**与顺序一起返回**，前端不做任何排序。
- 两个榜都与分类、搜索词无关，属于首页固定数据。

### 3. 头条区推荐站点（4 条）

宫格内除排行榜之外的推荐位，同时供第 1 项的超大卡取用。

- 需要**被标记为推荐的站点**，按后端默认顺序返回。
- 数量上需要 4 条：其中 2 条用于宫格卡右侧的推荐小卡，另外 2～3 条用于宫格内的推荐卡位（不同视口下占用格数不同，取 4 条可覆盖）。
- 与分类、搜索词无关，属于首页固定数据。

### 4. 筛选后的常规列表（分页）

用于下方常规卡片网格。

- 需要**标准分页结构**：当页数据列表、总条数、当前页、总页数。
- 必须支持后端已有的筛选与排序能力：分类、搜索关键字、精确关键词、身份、模块、设备、排序字段与方向。
- 首屏取第 1 页；翻页时前端只需递增页码，并接收新增的一页数据。

## 三、请求参数

### 3.1 需要前端传入的参数

以下参数**全部是后端 `/public/site/page` 已支持的字段**，本接口直接复用，不新增任何自定义参数。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| identityId | String | 否 | 身份 ID；有值时常规列表按该身份过滤 |
| categoryId | String | 否 | 当前选中分类，需级联包含其所有子分类；不传表示全部分类 |
| searchKey | String | 否 | 名称 / 描述 / 链接 模糊匹配 |
| keyword | String | 否 | 关键词精准匹配 |
| module | String | 否 | 所属模块 |
| device | String | 否 | `PC` / `MOBILE` / `COMPATIBLE`；不传则按请求 UA 判定 |
| size | Integer | 否 | 常规列表每页条数，默认 20，上限 100 |
| sortField | String | 否 | 常规列表排序字段：`orderNum` / `count` / `createTime`，默认 `orderNum` |
| sortOrder | String | 否 | 常规列表排序方向：`ASCEND` / `DESCEND`，默认 `ASCEND` |

### 3.2 需要后端自行决定的参数

以下区块的条数与排序**前端不传参**，由后端固定：

| 区块 | 需要后端固定的口径 |
| --- | --- |
| 排行榜 · 最新榜 | 按创建时间倒序，固定 5 条 |
| 排行榜 · 最热榜 | 按点击量倒序，固定 5 条 |
| 推荐站点 | 仅推荐站点，按后端默认顺序，固定 4 条（其中 1 条供超大卡使用） |

> **为什么不把这些做成请求参数**：`sortField` 是作用于整个分页查询的**单一排序字段**，一次请求无法同时产出「创建时间倒序」与「点击量倒序」两个榜。若为此新增参数，属于后端未定义的字段，因此约定由后端在接口内部固定实现。

## 四、响应需要包含的内容

响应统一遵循《后端响应规范》（成功时 `data` 返回，字段命名由后端按规范自行定义）。`data` 需要能一并取到以下 4 部分内容：

| 需要的数据 | 说明 |
| --- | --- |
| 排行榜 · 最新榜 | 站点数组，按创建时间倒序，5 条 |
| 排行榜 · 最热榜 | 站点数组，按点击量倒序，5 条 |
| 推荐站点 | 站点数组，4 条；第 1 条由前端兼作头条区超大卡 |
| 常规列表 | 标准分页结构，可包含与推荐站点重复的数据（两者本就独立） |

站点对象所需字段沿用 `BizSitePublicVo`（`id` / `name` / `logo` / `des` / `link` / `count` / `recommend` / `visible` / `background` / `cover` / `keyword` / `orderNum` / `module` / `createTime` / `categoryList` 等），前端需要用到的主要是：名称、LOGO、封面、描述、链接、点击量、创建时间、是否推荐。

## 五、对接约定

1. **分类树单独查询**：仍走已有的 `/public/site/categoryTree`，首屏先取分类，再调聚合接口。
2. 首屏调完这两个接口即可；翻页仍走已有的 `/public/site/page` 递增页码，新增数据追加到常规列表。
3. 搜索 / 切换分类时重新调用聚合接口，只影响常规列表；排行榜、推荐站点为固定区块，可由前端缓存复用（首次拿到后不必再请求）。
4. 推荐站点为空时，头条区超大卡与宫格推荐位一并降级为占位。
5. 点击跳转仍调用已有的 `/public/site/click` 上报点击量。
6. 所有 `/public/**` 接口免登录，图片类字段均为公开地址可直接使用。
7. 响应结构、状态码严格遵循《后端响应规范》，不新增自定义状态码。
8. **不新增请求参数**：本接口只接受 3.1 中列出的字段。若后续确需自定义区块条数或排序，须先在后端 `/public/site/page` 同步定义，再更新本文档，前端不得先行约定。
